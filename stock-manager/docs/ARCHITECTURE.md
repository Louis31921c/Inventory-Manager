# Architecture

Stock Manager is one local program. A desktop window (WebKit) shows pages served by a FastAPI app that listens on
`127.0.0.1` only, on a free port, and stops when the window closes. All data is one DuckDB file. Nothing is
reachable from outside the machine.

```
 window / browser ──► server.py (FastAPI) ──► domain modules ──► db.py ──► inventory.duckdb
                         │  middleware: licence gate, sign-in, role check, same-origin, security headers
                         └─ background loops: mail (15 min), order queue (hourly), the hourly loop, photo purge (daily)
```

The pipeline, step by step, is in [pipeline.html](pipeline.html) (generated by `tools/pipeline_schema.py`).

## Where things live

| What | Where | Who may change it |
|---|---|---|
| Program (code, pages, prompts, rule defaults) | the installed `inventory` package | nobody: signed by the vendor, checked at start (`integrity.py`) |
| Data | `~/.local/share/stock-manager/inventory.duckdb`, photos beside it | the program, through its screens |
| Settings | `~/.config/stock-manager/settings.env` (secrets encrypted) | the licensee, on the System screens |
| Accounts | `~/.config/stock-manager/account.json` (scrypt hashes) | an administrator, on the Users card |
| Licence | `~/.config/stock-manager/license.json` | installed from the vendor's file |
| Encryption key | `~/.config/stock-manager/vault.key`, or the OS keyring | nobody; back it up |
| Rule files for the agents | `BOT_RULES_DIR` (optional) | the licensee; the code enforces the numbers again |

## Layers

1. **Pages** (`web_ui/`): one HTML page, `sap.css`, plain JavaScript, no framework and no network calls to other sites.
2. **API** (`server.py`): routes grouped by topic; every request passes the middleware chain above. `access.py` is the
   whole permission table.
3. **Domain modules**: one file per concern (below). They take a `db_path`, return plain dicts and raise `ValueError`
   with a sentence a person can read.
4. **Platform**: `db.py` (connections, queries), `migrations.py` (numbered, forward only), `config.py`, `vault.py`,
   `audit.py` (hash-chained), `backup.py` (encrypted).

## Agents

Two agents, both run through the Claude command line on the machine (no API key): **Plutus** buys and **Terminus**
reads names and decides held baskets. Each has a charter: numbers a person sets, enforced again in code on whatever
the model answers. Both start off, then dry run for three days, then live. See `agents.py`, `charters.py`,
`purchasing.py`, `judge.py`.
